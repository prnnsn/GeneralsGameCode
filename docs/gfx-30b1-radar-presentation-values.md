# GFX 30b.1 / 32b pilot — radar presentation values

Base 669bdff725182da2b279bc8f7787a55ddab2f837, following #107 / #120. This is a same-thread snapshot refactor, not movement interpolation. The current six-simulation-frame refresh condition, refreshObjects path, visibility policy, stealth alpha, 2x2 footprint, list order, integer coordinates, clipping and one checked mip mapping remain unchanged. Capture the visible object values before taking the texture map; the rasterizer sees only values, not Object/RadarObject/Player pointers. Use a reusable scratch vector and clear its size after every update; no history or serialization. The mapped texture dimensions still determine final clipping. A failed map continues to leave the old overlay as before. The extra temporary CPU storage and collection before a failed map are deliberate tradeoffs; measure with #121, and do not claim a performance improvement. No new Renderer methods or native DX calls. Works with the same single-mip mapping contract in the future DX11 backend.

The existing GameClient::getFrame is a simulation-frame counter, so repeated render frames at a divisible tick can rebuild the same overlay. Do not change the refresh trigger yet: visibility may change between draws and failed uploads must remain retryable. Future 30b.2 must record two authorized visible positions for the same stable object identity, reset at new map/load/observer change, disappearance, teleport or discontinuity, use FramePacer phase without extrapolation, and avoid stale enemy positions. Preserve authoritative radar interaction and shroud. The 128x128 grid itself limits subpixel smoothness; compare higher-resolution visual layer or batched screen-space markers independently, without changing logical radar hit-testing or using a DX8-specific draw path.
