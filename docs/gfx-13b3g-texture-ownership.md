# GFX 13b.3g — ordinary 2D texture allocation and ownership

Follow #92, #97, #99 and the resource contract #86. Baseline f83baba8079d7206527ab313d37c439cc5d6de2e. Implementation brief, not a completed implementation. Coordinate with #93 (13b.3e) and #94 (13b.3f); review shared Renderer declarations when rebasing. Do not require the terrain migration to finish before investigating this slice.

## Source evidence and boundary

Core/Libraries/Source/WWVegas/WW3D2/Renderer.h currently exposes a borrowed RenderTexture2DHandle with void* value. Map_Texture_2D_Mips / Unmap_Texture_2D_Mips from #99 assume the task retains ownership. textureloader.cpp Begin_Compressed_Load and Begin_Uncompressed_Load call DX8Wrapper::_Create_DX8_Texture; Begin_Load releases on map failure; End_Load releases on failure and applies the missing texture; Apply calls Texture->Apply_New_Surface and releases the task's native reference. The shared TextureBaseClass::Set_D3D_Base_Texture updates LastAccessed and releases/addrefs native pointers. Cube, volume, depth, thumbnail, synchronous surface, and reset-tracked allocations are separate paths. Check USE_MANAGED_TEXTURES variants, including UpdateTexture before publication, instead of assuming only the default configuration.

## Implementation

- Add a narrow neutral 2D creation descriptor (logical WW3D format, dimensions, requested/resolved mip count, usage, CPU access and recreation intent); reuse checked layout helpers, retain exact DX8 allocation arguments, caps/reduction/fallback decisions and actual native format. Explicitly handle auto mip count before validating the resulting resource. No enum renumbering or new file format.
- Define backend-controlled owning reference, borrowed view and explicit transfer/publication contract. Avoid a new global manager; preserve W3D object identity and existing refcounts. No new public native-pointer escape; keep compatibility bridge local to DX8 until remaining legacy consumers migrate. Do not reinterpret a borrowed void* as an owning handle. Handle self-replacement and retain/release order safely; preserve access timestamp and missing texture ownership.
- Migrate only the ordinary 2D loader allocation/release/publication path, including compressed and uncompressed starts, normal completion, failure, detach and foreground demand load. Reuse #99 mapping (or narrowly adapt its handle interface without changing map order/flags); preserve #97 staging and soft 16 MiB threshold. No publication until all relevant work succeeds. Retain ownership across map/unmap and deferred worker completion, release exactly once. Keep API operations on the correct render thread.
- Keep old behavior for legacy native consumers, cube/volume, depth, thumbnail, conversion paths not in scope and reset-managed resources; explicitly record remaining escape paths and follow-up ownership. Do not introduce DX11 code in this slice, change SIM/RNG/network, or claim full neutral ownership of every texture.
- For the next 13b.3h slice, audit remaining regular 2D upload paths and move CPU preparation to owned staging before render-thread upload without increasing unbounded queue memory. Preserve DDS/TGA/tint/fallback and actual allocation choices; this is not part of 13b.3g.

## Acceptance

Unit/differential tests: allocation failure, invalid descriptor, fallback, actual resolved mip count, normal and failed map/unmap, failed publication, cancellation/detach, self-replacement, missing texture reference, same-object reuse and balanced release; compare native arguments/ref counts and queue order with DX8 baseline. Check render-thread access, reset/reload and repeated level loads. Test existing supported managed configuration, report other build guards explicitly. Both games and both World Builders Win32 Release and both unit suites; use verified mod assets for intact/damaged model texture checks, texture reductions 0 and 2, return to menu/new match, Alt+Tab; record exact results and rollback. No automatic merge; no claim of DX11 compatibility.
